# Storylet ranking model

This folder defines the generic preference-data contract and the EmbeddingGemma 2 encoder fine-tuning path. It has no story-world defaults. Dataset rows are JSONL objects matching `ranking-example.schema.json`; scenario families must be disjoint across `train`, `validation`, and `held_out`. Training may include `rule_synthetic` or `strata_synthetic` labels, but validation and held-out rows must be marked `human_reviewed`.

Run the lightweight contract tests with `uv run --project model --no-sync python -m unittest discover -s model/tests -v`. On Windows, set up the GPU environment with `uv venv --project model --python 3.13`, `uv pip install --python model/.venv/Scripts/python.exe torchao`, `uv pip install --python model/.venv/Scripts/python.exe unsloth --torch-backend=auto`, and `uv pip install --python model/.venv/Scripts/python.exe "sentence-transformers>=6.1"`. Then run `uv run --project model --no-sync python model/train_embedding_ranker.py <dataset.jsonl>`. EmbeddingGemma 2 is never trained with FP16; the trainer uses BF16 when the GPU supports it and FP32 otherwise.

Preference examples carry nine bounded features: semantic relevance, urgency, pacing alignment, novelty, waiting time, goal progress, role-binding quality, predicted consequence alignment, and no-action preference. The trainer recomputes semantic relevance with the selected encoder, fine-tunes the encoder, then fits a deterministic pairwise logistic ranking head and exports `ranking-head.json`. That head is versioned from the dataset hash and immutable base-model revision. The trainer records the same provenance, family splits, label sources, hardware, and before/after encoder and head metrics in metadata. A successful training command is not acceptance by itself: held-out metrics must be reviewed against the saved base-model baseline.

To use a reviewed head, set `STORYLET_RANKING_HEAD` to the JSON artifact when starting `model/embedding_service.py`. The optional loopback endpoint `/v1/ranking-head` serves the validated artifact to the studio, which passes feature vectors to the Rust engine for scoring. Without the variable, ranking falls back to the uncalibrated encoder baseline. `goal_progress` and `predicted_consequence_alignment` currently use neutral values in live playtests until a project authors goal and consequence models; these fields can still be supervised from reviewed ranking data. Probabilities remain explicitly uncalibrated either way.

For a live end-to-end smoke test, run `bun run scripts/smoke-semantic-director.ts`. It starts the local embedding service, creates a generic two-scene playtest with in-memory session storage, ranks the eligible scenes, verifies the pinned encoder revision, and stops its child processes. In the studio, the playtest Director panel exposes the same path through **Rank with local encoder**; configure `STORYLET_EMBEDDING_URL` if the service is not listening on `127.0.0.1:4318`. The base encoder produces an uncalibrated relevance baseline, so the UI labels its probabilities as provisional. Use a reviewed adapter only after the held-out evaluation gate passes.
